# Human 2.0 Manuscript Architecture

## Canonical manuscript

The publisher review changed the book from a 41-chapter textbook outline into a tighter three-part manuscript. The canonical queue is **20 chapters**:

### Part I — Crash Course (6 chapters)

Only the mechanics needed to operate agents intelligently. Each chapter ends with an operator rule and measurable test.

### Part II — Human 2.0 in the Wild (8 chapters)

The spine of the book: personal scenes, artifacts, numbers, consequences, failures, and the lived proof case.

### Part III — Running the Day (6 chapters)

The operating manual: establish the baseline, then repeat Direct → Route → Execute → Verify → Learn, ending with what must remain human.

## Publisher decisions to implement

- Open with the lab and a lived result or failure, not tokens.
- Six agents are a proof case, not a shopping list.
- Use the operating loop as a recurring framework.
- Add the Human 1.0 baseline before claiming an upgrade.
- Include an adoption path: one agent, one recurring workflow, one verifier; scale only on evidence.
- Keep a claim ledger for every number, date, price, and product behavior.
- State where agents failed and how the human caught it.
- Every chapter ends with an operator rule and measurable test.
- The final chapter names what should never be delegated: responsibility, taste, consent, priorities, relationships, and consequences.
